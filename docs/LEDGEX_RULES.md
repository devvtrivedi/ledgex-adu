## 3. A-1.1 licence gate and document repair

Why the gate covers internal facts

Jurisdiction resolution is load-bearing. If city_limits is touched to decide whether a parcel belongs to San Jose, that fact participates in
composition even when it is not printed. Allowing an unknown-rights boundary fact to pass internally would let every downstream fact
inherit a commercial use that was never cleared. LICENCE_UNKNOWN at L0 is therefore the intended fail-closed result, not a defect. Do
not add an override flag, gate-only source class or internal-use exemption. Confirm rights or refuse.

> **HISTORICAL DEFECT NOTE**

The first generated Spec v1.6 file abbreviated the invariant table and contained two top-level sections numbered 14. Its corrected file
version repaired both. Spec v1.7 carries the full table forward and preserves one §14 with §14.1 and §14.2.

Prohibited response to L0

- Do not treat LICENCE_UNKNOWN as an availability error.

- Do not retry through a different unvalidated or uncleared source.

- Do not let subscription status, customer identity or output scope weaken I6.

- Do not store a manually observed jurisdiction answer as a fact.

## 4. A-1.2 evaluation-to-permit outcome loop

Begin recording Base evaluation intent in Phase 1. A scheduled matcher later joins immutable Property File requests to CC0 permit facts
over a versioned lag-window method. It produces Track B observations showing which evaluated parcels later became projects. No user
report-back is required, and no observation is a customer fact.

Operational rules

- The loop lives in commerce/. It may read public facts; public never references commerce.

- Every observation stores method_version, config hash, exact window, source snapshot and any matched permit fact.

- Observations are immutable. A better matcher creates a new run and new observations; it never rewrites history.

- Only a CC0 permit source may label a match under this loop. Rights failure aborts the run.

- Track B aggregates internally. core/compose and renderers cannot import or query observation modules.

- No lag duration, conversion threshold or success criterion is set in these Rules.

> **CANNOT BE BACKFILLED**

Permit history can be re-read, but professional evaluation intent cannot be reconstructed if the original request row was never recorded.
The request record and matcher schema ship in Phase 1 even if no match appears for a long period.

I19 makes this boundary a merge gate rather than a convention.

## 5. A-1.3 validated footprint-provider slot

A jurisdiction has one active footprint-provider slot. Any provider version may be registered inactive. It can occupy the slot only after an
immutable approved measured-error record exists for the same provider version, method and jurisdiction.

Activation and runtime rules

- geometry_tier_enabled remains false while the slot is empty or its provider lacks approved validation.

- Measured-error values and benchmark evidence are stored; this revision invents no numeric acceptance threshold.

- A second provider can be validated and selected by a controlled configuration change without schema or composer rewrite.

- Selection is not fallback. If the active provider fails during a request, placement and dependent conclusions refuse; runtime never chooses
another provider.

- Base Core continues under I10 when a provider is present but inactive.

> **REQUIRED TESTS**

test_geometry_provider_requires_validation; test_geometry_slot_single_active; test_base_core_without_ld4; test_no_geometry_fallback.
The last two run with a footprint_provider row present but inactive.

I20 makes activation fail in the database; an application convention is insufficient.

## 6. A-1.4 edge infrastructure protection

Product entitlement and infrastructure protection are separate. The edge request guard runs before resolve, entitlement checks and
core/compose. A rejected request returns HTTP 429 and creates no Property File request, file, refusal or fourth outcome.

Contract

- Protect limited-free endpoints and any other route selected by an approved edge policy.

- Policy identity, version and hash are required deployment configuration; these Rules set no numeric rate, window or allowance.

- A missing or invalid production policy fails service startup for a protected route.

- Edge rejection occurs before source retrieval and composition cost is incurred.

- 429 telemetry is infrastructure telemetry. It is not an entitlement balance, credit event or Property File outcome.

- No staff queue, exception or manual release path exists.

> **REQUIRED TESTS**

test_edge_guard_precedes_resolve; test_edge_429_creates_no_file_or_request; test_edge_guard_independent_of_entitlement;
test_protected_route_requires_policy.
